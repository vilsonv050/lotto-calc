# Общий контекст проекта Codex GPT

Этот файл — общая память проекта для работы с разных компьютеров и из разных чатов Codex. GitHub-репозиторий `vilsonv050/lotto-calc`, ветка `main`, является единственным источником истины. Чаты сами по себе не синхронизируют память: в начале работы нужно прочитать этот файл, а после значимого изменения — обновить его в том же коммите, что и рабочие файлы.

## Назначение проекта

В папке `Codex GPT` разрабатываются автономные JavaScript-bookmarklet-скрипты для исследования `https://nloto.ru/`. Основной текущий скрипт собирает статистику тиражей, комбинации, финансовые показатели и ссылки на официальные результаты.

Работа первоначально велась на другом компьютере в `E:\Codex GPT`. 30 июля 2026 года файлы были сохранены в GitHub, чтобы продолжать работу с нескольких компьютеров без ручного переноса.

## Восстановленная хронология

### Исходный файл

`Статистика Тиражей.txt` был первым рабочим вариантом. Он сохранён как исторический исходник и не должен изменяться.

### Версия с датой — `Статистика Тиражей_29-07-26.txt`

Основные изменения:

- архив загружается страницами до 200 тиражей вместо перебора каждого номера;
- добавлены режимы полной и быстрой загрузки;

- статистика адаптирована под лотереи с одним, двумя и тремя игровыми полями;
- даты и экспорт CSV нормализованы;
- известные `productId` были сверены с фактической структурой сайта.

### V1 — `Статистика Тиражей_29-07-26_V1.txt`

Исправлена загрузка финансовых данных:

- полной статистике возвращён режим по умолчанию;
- исправлен источник детальных данных;
- комбинации корректно объединяются с количеством билетов, выплатами и другими финансовыми полями;

Пример: `101051` — версия «Великолепной 8» до обновления, `109031` — новая версия после обновления, пока без тиражей.

### V3 — `Статистика Тиражей_29-07-26_V3.txt`

- показатель `ROI` переименован в точное «Выплата%»;
- обновлён CSV-экспорт;
- компактный список лотерей сохранён;

- будущие записи содержат номер, дату и время розыгрыша, окончание продаж, цену, признак страховки, акцию и её описание; у некоторых игр присутствует объект дополнительных призов;

- блок загружается как при проверке последнего тиража, так и при обычной загрузке статистики;
- для лотереи без завершённых тиражей интерфейс всё равно может показать доступные будущие записи.

## Правило версий файлов

- Исторические версии не перезаписывать.
- Первая новая версия за день: `Статистика Тиражей_ДД-ММ-ГГ.txt`.
- Следующие версии того же дня: `_V1`, `_V2`, `_V3` и далее.
- Перед созданием файла проверить существующие имена в папке и выбрать следующий свободный номер.

## Протокол синхронизации между компьютерами и чатами

1. Перед началом работы проверить чистоту рабочей копии и получить свежий `main` из GitHub.
2. Прочитать `AGENTS.md` и этот файл полностью.
3. Работать только от последней версии в `main`.
4. После значимой работы обновить разделы «Текущая каноническая версия», «Последнее незавершённое направление» и журнал ниже.
5. Коммитить рабочий файл и обновление контекста вместе.
6. Не хранить здесь пароли, токены, cookies, персональные данные или полный сырой лог инструментов.
7. Не использовать force-push. При расхождении двух компьютеров сначала сохранить локальные изменения, затем выполнить обычное получение и rebase/merge с ручным разрешением конфликта.
8. Использовать `SYNC_GITHUB.ps1 status` для проверки, `SYNC_GITHUB.ps1 pull` перед работой и `SYNC_GITHUB.ps1 push` после проверенного коммита. На Windows запускать через `powershell -ExecutionPolicy Bypass -File .\SYNC_GITHUB.ps1 <действие>`.
